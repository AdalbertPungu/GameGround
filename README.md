# GameGround

**Grounded Football Intelligence**

A .NET football intelligence prototype that transforms match events into
grounded observations and verified match narratives through deterministic
analysis and agent-based workflows.

GameGround turns football match events into grounded, verified intelligence.
Its Analyst and Narrator have distinct roles, while deterministic verification
gates control their handoff, bounded revisions and final publication. The
intended users are analysts, broadcasters and streaming teams who need to
distinguish recorded facts from unsupported interpretation.

## What works today

- Local JSON validation and replay, deterministic football intelligence and
  source-event provenance.
- A typed Microsoft Agent Framework workflow with isolated per-run state,
  approved-observation-only narration and fail-closed publication.
- Reproducible **simulated Analyst and Narrator** demonstrations through existing
  tests. Their output is deterministic, not generated by a live LLM.
- Opt-in model-backed adapters using `Microsoft.Extensions.AI` / `IChatClient`,
  plus separate local-model evaluation infrastructure. One real end-to-end run
  was validated on 2026-10-22 using an isolated external runner with OpenRouter
  and `dots-studio/dots-3-note-preview:free`: 6 Analyst observations and 6
  published verified narrative claims, with unchanged adapters and gates.
  This external experiment is not a bundled cloud CLI or the default demo;
  free-provider availability is not guaranteed. The offline path remains default.

This is a local .NET backend/workflow prototype, not a web application or a
deployed broadcast product. There is no frontend, audience personalization,
Microsoft Foundry integration or Azure hosting. Microsoft technology actually
used here is C#/.NET, Microsoft Agent Framework and Microsoft.Extensions.AI.

All demonstrated football data is synthetic. The reference fixture contains
two fictional teams, four players, 20 events and two 60-second periods. It is
a contract miniature, not real Premier League data or a full-match realism
benchmark. No xG, speed, distance, formations or tactical dominance is inferred.

## Prerequisites and build

Run the following PowerShell commands from the solution root. Use .NET SDK
**10.0.300**, selected by [global.json](global.json), with its compatible runtime.
No API key, Ollama, local model or cloud account is needed for the offline path.

A fresh checkout needs NuGet dependencies restored once. This can require
network access to package sources; subsequent commands below do not restore
packages or invoke a model.

```powershell
dotnet --version
dotnet restore GameGround.sln
dotnet build GameGround.sln --configuration Release --no-restore
dotnet test GameGround.sln --configuration Release --no-build --no-restore
dotnet format GameGround.sln --verify-no-changes --no-restore
```

Validation on 2026-10-23: **541 passed, 0 failed, 0 skipped**; Release build
with **0 warnings, 0 errors**; formatting verification passed. The build/test
commands were run with cached dependencies; a fresh-machine restore was not
retested. Tests use scripted models/in-memory transports, not live inference.

## Offline demonstration

### 1. Validate and replay the synthetic fixture

```powershell
dotnet run --project tools\GameGround.Cli --configuration Release --no-build --no-restore -- validate data\synthetic\match-001.json
dotnet run --project tools\GameGround.Cli --configuration Release --no-build --no-restore -- replay data\synthetic\match-001.json
```

Expected: `Validation: valid (synthetic)`, `Events: 20`,
`Score: Harbor FC 1-1 Meadow United`; replay additionally reports
`sequence=20; period=2; clock=00:01:00; status=Ended; complete=True`.
Both commands return exit code 0.

### 2. Show the simulated workflow's published state

The existing local-orchestrator oracle test prints its entire verified state.
Save the verbose output outside the repository rather than scrolling through
it during the presentation:

```powershell
$demoLog = Join-Path $env:TEMP "gameground-offline-demo.txt"
dotnet test tests\GameGround.Tests\GameGround.Tests.csproj --configuration Release --no-build --no-restore --filter "FullyQualifiedName~Reference_workflow_is_verified_end_to_end_without_external_runtime" --logger "console;verbosity=detailed" > $demoLog
if ($LASTEXITCODE -ne 0) { throw "Offline workflow demonstration failed." }
$log = Get-Content -LiteralPath $demoLog -Raw
$start = $log.IndexOf('{')
$end = $log.LastIndexOf('}')
if ($start -lt 0 -or $end -le $start) { throw "Workflow JSON output missing." }
$state = $log.Substring($start, $end - $start + 1) | ConvertFrom-Json
$state | Select-Object Status, @{Name="Observations";Expression={$_.Observations.Count}}, @{Name="PublishedClaims";Expression={$_.NarrativeClaims.Count}}, @{Name="Verifications";Expression={$_.Verifications.Count}}
$state.NarrativeClaims | Select-Object -First 6 Text, Status
```

Expected: 16 approved observations, 16 narrative claims and 32 verification
attempts. JSON serializes enums numerically: workflow status `3` is `Completed`;
claim status `1` is `Verified`. Example outputs include Harbor FC pass completion
`50% (1/2)` and Meadow United `100% (1/1)`, explicitly scoped to sequences 1-20.
Claims retain fact IDs, evidence and covered source-event IDs in `$state`.
Here, publication means verified claims in terminal workflow state, not delivery
to an external service.

### 3. Exercise the actual Agent Framework graph and rejection gates

```powershell
dotnet test tests\GameGround.AgentFramework.Tests\GameGround.AgentFramework.Tests.csproj --configuration Release --no-build --no-restore --filter "FullyQualifiedName~FrameworkWorkflowTests" --logger "console;verbosity=normal"
```

This is a test-harness demonstration, not a separate workflow CLI or UI.
The tests execute the SDK workflow independently of `LocalOrchestrator` and
compare verified outcomes with that oracle for every fixture prefix 0-20.
Named checks show:

- `Happy_path_hands_off_only_verified_observations_and_publishes_verified_claims`:
  approved-only handoff and verified final claims.
- `Invalid_analyst_batch_is_preserved_as_rejected_and_never_reaches_narrator`:
  no narration or publication from a rejected batch.
- `Unsupported_narrative_is_rejected_without_partial_publication`:
  unsupported wording blocks the whole narrative batch.
- `Rejected_stage_revises_with_feedback_then_matches_the_oracle` and
  `Revision_exhaustion_is_bounded_for_both_roles`: feedback, bounded retries and
  rejection without publication when the configured limit is exhausted.
- Additional class tests cover cancellation, timeouts, late results, numeric
  mismatches, future-event leakage, repeatability and concurrent isolation.

The verifier validates typed facts, provenance and closed supported wording.
It does not prove arbitrary natural-language semantic truth. Default workflow
policy permits one revision per stage; individual tests also exercise other
explicitly bounded policies. No safety boundary is disabled for the demo.

The offline prototype is technically reproducible, but a submission is not
complete until the public links and other requirements above are satisfied.
The lack of a bundled cloud-inference launch path, lack of a rendered/personalized
