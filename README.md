
# GameGround

### Grounded Football Intelligence

GameGround is a .NET football intelligence prototype that transforms match events into grounded observations and verified match narratives through deterministic analysis and agent-based workflows.

GameGround turns football match events into grounded, verified intelligence. Its Analyst and Narrator have distinct roles, while deterministic verification gates control their handoff, bounded revisions, and final publication.

The project explores how analysts, broadcasters, and streaming teams could distinguish recorded football facts from unsupported interpretations.

## Project pitch

GameGround demonstrates how agent-based workflows and deterministic verification can turn football match events into traceable observations and evidence-grounded narratives.

Its Analyst produces structured observations from available match evidence. Its Narrator transforms approved observations into readable claims. Verification gates check evidence, provenance, and supported wording before a narrative can be published.

The goal is not simply to generate football commentary, but to make each claim traceable to the available evidence and reject unsupported statements.

The current offline demonstration uses synthetic match data and simulated agent roles. It demonstrates the workflow and its verification controls, not live LLM inference.

## What works

- Local JSON dataset validation and replay.
- Deterministic football intelligence calculations and source-event provenance.
- A typed Microsoft Agent Framework workflow with isolated per-run state.
- Approved-observation-only narration and fail-closed publication.
- Reproducible simulated Analyst and Narrator demonstrations through automated tests.
- Opt-in model-backed adapters using `Microsoft.Extensions.AI` and `IChatClient`.
- Separate infrastructure for local-model evaluation.

A real end-to-end model-backed run was validated on October 22, 2026, using an isolated external runner with OpenRouter and `dots-studio/dots-3-note-preview:free`. That experiment produced six Analyst observations and six published, verified narrative claims.

This external experiment is not a bundled cloud-inference CLI or the default demonstration. Free-provider availability is not guaranteed.

**The offline path remains the default demonstration.** Its agent outputs are simulated and deterministic, not generated by a live LLM.

GameGround does not currently include a Microsoft Foundry integration or Azure hosting.

## Scope and limitations

GameGround is a local .NET backend and workflow prototype, not a web application or deployed broadcast product.

The current project does not provide:

- A frontend or audience-facing application.
- Audience personalization.
- A bundled cloud-inference launch path.
- Microsoft Foundry integration.
- Azure hosting.

### Synthetic football data

All demonstrated football data is synthetic.

The reference fixture contains:

- Two fictional teams.
- Four fictional players.
- Twenty events.
- Two periods of sixty seconds each.
- A final synthetic score of 1–1.

The dataset is a small contract-testing fixture, not real Premier League data or a realistic full-match benchmark.

The engine does not infer expected goals (xG), ball speed, distance covered, formations, heatmaps, or tactical dominance from data that does not contain the required evidence.

- .NET SDK `10.0.300`, selected by `global.json`.

## Getting started

Clone the public repository:

```powershell
git clone https://github.com/AdalbertPungu/GameGround.git
cd GameGround
```

Check the SDK version:

```powershell
dotnet --version
```

Restore dependencies:

```powershell
dotnet restore GameGround.sln
```

Build the solution:

```powershell
dotnet build GameGround.sln --configuration Release --no-restore
```

Run the test suite:

```powershell
dotnet test GameGround.sln --configuration Release --no-build --no-restore
```

Verify formatting:

```powershell
dotnet format GameGround.sln --verify-no-changes --no-restore
```

## Offline demonstration

The following commands demonstrate dataset validation and deterministic replay using the synthetic reference fixture.

### 1. Validate the dataset

```powershell
dotnet run --project tools\GameGround.Cli --configuration Release --no-build --no-restore -- validate data\synthetic\match-001.json
```

Expected summary:

```text
Validation: valid (synthetic)
Events: 20
Score: Harbor FC 1-1 Meadow United
```

### 2. Replay the dataset

```powershell
dotnet run --project tools\GameGround.Cli --configuration Release --no-build --no-restore -- replay data\synthetic\match-001.json
```

Expected final state includes:

```text
sequence=20
period=2
clock=00:01:00
status=Ended
complete=True
```

Both commands should return exit code `0` for the valid reference fixture.

### 3. Demonstrate the verified offline workflow

The local-orchestrator reference test prints the workflow's verified state. Save the verbose output to a temporary file so that it can be inspected during a presentation.

```powershell
$demoLog = Join-Path $env:TEMP "gameground-offline-demo.txt"

dotnet test tests\GameGround.Tests\GameGround.Tests.csproj --configuration Release --no-build --no-restore --filter "FullyQualifiedName~Reference_workflow_is_verified_end_to_end_without_external_runtime" --logger "console;verbosity=detailed" > $demoLog

if ($LASTEXITCODE -ne 0) {
    throw "Offline workflow demonstration failed."
}

$log = Get-Content -LiteralPath $demoLog -Raw
$start = $log.IndexOf('{')
$end = $log.LastIndexOf('}')

if ($start -lt 0 -or $end -le $start) {
    throw "Workflow JSON output missing."
}

$state = $log.Substring($start, $end - $start + 1) | ConvertFrom-Json

$state | Select-Object Status,
    @{Name="Observations";Expression={$_.Observations.Count}},
    @{Name="PublishedClaims";Expression={$_.NarrativeClaims.Count}},
    @{Name="Verifications";Expression={$_.Verifications.Count}}

$state.NarrativeClaims | Select-Object -First 6 Text, Status
```

Expected reference results:

- 16 approved observations.
- 16 narrative claims.
- 32 verification attempts.
- Workflow status `3`, representing `Completed`.
- Claim status `1`, representing `Verified`.

Example claims include Harbor FC pass completion of 50% (1/2) and Meadow United pass completion of 100% (1/1). These statistics are explicitly scoped to events 1–20 of the synthetic fixture.

The workflow's published state means that claims have been verified in the terminal workflow state. It does not mean that claims were delivered to an external publication service.

### 4. Exercise the Agent Framework graph and rejection gates

Run the Agent Framework workflow tests:

```powershell
dotnet test tests\GameGround.AgentFramework.Tests\GameGround.AgentFramework.Tests.csproj --configuration Release --no-build --no-restore --filter "FullyQualifiedName~FrameworkWorkflowTests" --logger "console;verbosity=normal"
```

This is a test-harness demonstration, not a separate workflow CLI or user interface. It executes the SDK workflow independently of the local orchestrator and compares verified outcomes against the reference oracle for fixture prefixes 0–20.

Named checks include:

- `Happy_path_hands_off_only_verified_observations_and_publishes_verified_claims`
- `Invalid_analyst_batch_is_preserved_as_rejected_and_never_reaches_narrator`
- `Unsupported_narrative_is_rejected_without_partial_publication`
- `Rejected_stage_revises_with_feedback_then_matches_the_oracle`
- `Revision_exhaustion_is_bounded_for_both_roles`

Additional tests cover cancellation, timeouts, late results, numeric mismatches, future-event leakage, repeatability, and concurrent isolation.

The verifier checks typed facts, provenance, and supported wording. It does not prove arbitrary natural-language semantic truth. The default workflow permits one revision per stage, and rejected or unsupported output must not be published.
